# 무료급식 출석 서버 자동 업데이트

## 목적과 범위

- 대상은 Windows에서 실행하는 **서버 JAR**이며 Android APK는 포함하지 않는다.
- 서버를 시작할 때만 최신 버전을 한 번 확인한다. 운영 시간 중 주기 확인·자동 재시작은 하지 않는다.
- 업데이트 서버가 닿지 않아도 기존 정상 JAR를 실행한다.
- `data/`의 명단·월별 출석 일지·로그는 업데이트 대상이 아니다.

## Ubuntu 배포처

이 도메인은 Cloudflare DNS와 Cloudflare Tunnel을 사용한다. Ubuntu 서버에 공인 IP용 DNS A 레코드를 만들지 않는다.

Cloudflare Zero Trust에서 현재 Ubuntu에 연결된 기존 Tunnel의 **Public Hostname**을 추가한다.

```text
Hostname: bgrc.howmanycals.online
Service:  http://localhost:80
```

Public Hostname을 저장하면 Cloudflare가 Tunnel을 가리키는 DNS 레코드를 관리한다. 브라우저와 Windows launcher는 Cloudflare의 HTTPS를 사용하고, Ubuntu 안에서는 cloudflared가 Nginx의 80 포트로만 연결한다. 따라서 이 업데이트 서버에는 공유기 포트 포워딩·공인 IP·Certbot 인증서가 필요 없다.

```text
/srv/bgrc-updates/
├─ incoming/                 # Tailscale SSH로 JAR을 먼저 업로드하는 임시 위치
└─ public/
   ├─ releases/              # 검증이 끝난 버전별 JAR
   └─ stable/
      ├─ manifest.json       # 최신 버전 정보
      └─ manifest.json.sig   # Ed25519 서명
```

Nginx 설정은 [bgrc.howmanycals.online.conf](../deploy/update-server/nginx/bgrc.howmanycals.online.conf)를 사용한다. 이 설정에는 `proxy_pass`가 없으므로 WCForge Java API·MySQL과 연결되지 않는다.

Cloudflare Public Hostname을 만든 뒤에만 서버에서 다음을 수행한다.

```bash
sudo install -d -o root -g www-data -m 0755 /srv/bgrc-updates/public/{releases,stable}
sudo install -d -o feralshining -g www-data -m 0750 /srv/bgrc-updates/incoming
sudo install -m 0644 deploy/update-server/nginx/bgrc.howmanycals.online.conf \
  /etc/nginx/sites-available/bgrc.howmanycals.online.conf
sudo ln -s /etc/nginx/sites-available/bgrc.howmanycals.online.conf \
  /etc/nginx/sites-enabled/bgrc.howmanycals.online.conf
sudo nginx -t
sudo systemctl reload nginx
```

릴리스 파일은 Tailscale SSH로만 올리고, 공개 Nginx에는 파일을 쓰는 권한을 주지 않는다. 운영 전에는 Nginx의 `limit_rate 2m`로 다운로드가 WCForge 대역폭을 과도하게 쓰지 않는지 확인한다. Cloudflare Tunnel의 Public Hostname을 먼저 만들면 Nginx 설정 전에는 404가 나오는 것이 정상이다.

## 서명 키

개인키는 개발 PC에만 두고 Git·Windows 설치 폴더·Ubuntu에는 저장하지 않는다.

```bash
openssl genpkey -algorithm ED25519 -out bgrc-update-private.pem
openssl pkey -in bgrc-update-private.pem -pubout -outform DER | base64 | tr -d '\n'; echo
```

두 번째 명령의 Base64 출력은 Windows 설치 폴더의 `config/launcher.properties`에 `update.publicKeyBase64` 값으로만 넣는다.

## 릴리스 만들기

```bash
export JAVA_HOME=/경로/Java17
export PATH="$JAVA_HOME/bin:$PATH"
sh gradlew test packageWindowsDistribution

java -cp launcher/build/libs/attendance-launcher-1.2.0.jar \
  com.bgrc.attendance.launcher.UpdateManifestTool \
  --version 1.2.0 \
  --jar build/libs/attendance-1.2.0.jar \
  --private-key /안전한/경로/bgrc-update-private.pem \
  --release-directory /임시/출석업데이트/public/releases \
  --stable-directory /임시/출석업데이트/public/stable \
  --base-url https://bgrc.howmanycals.online
```

먼저 `releases/attendance-버전.jar`을 Ubuntu에 올리고 SHA-256을 확인한다. 그 뒤 `stable/manifest.json`과 `manifest.json.sig`를 **마지막에** 올려 교체한다. 이렇게 하면 launcher가 덜 올라간 JAR을 내려받지 않는다.

## Windows 설치와 실행

```text
C:\BGRC-Attendance\
├─ launcher\attendance-launcher.jar
├─ launcher\run-attendance-launcher.bat
├─ config\launcher.properties
├─ versions\attendance-1.2.0.jar
└─ data\
```

`run-attendance-launcher.bat`은 설치 루트를 작업 폴더로 고정한 뒤 launcher를 실행한다. launcher는 새 버전을 서명·SHA-256·`/api/version`으로 검증한다. 새 버전이 45초 안에 기동되지 않으면 직전 JAR를 다시 실행한다.

`build/distributions/bgrc-attendance-1.2.0-windows.zip`은 Windows 설치본의 기본 골격을 한 번에 담는다. 단, 실제 자동 업데이트를 켜기 전에는 `config/launcher.properties`의 `update.publicKeyBase64`에 공개키를 설정해야 한다. 빈 값으로 두면 launcher는 업데이트만 건너뛰고 현재 JAR를 실행한다.

기동 검증에 실패한 새 버전은 `config/launcher.properties`의 `failed.version`으로 기록되어, 다음 서버 시작에서 재시도하지 않는다. 수정본은 반드시 더 높은 버전 번호로 배포한다. 새 버전이 정상 기동되면 이 값은 자동으로 지워진다.
